title: Upgrading
description: Move between Proa versions and find what broke.

Check `Cargo.lock` for the versions of the Proa crates your application uses. The facade, RSJS, fonts, and CLI can have different versions. Review the changes for the packages you use in the [release notes](https://github.com/proa-labs/proa/releases).

For a registry dependency such as `proa_core = "0.3"`, Cargo can update the lockfile within the 0.3 series. To move to another published minor, first change the requirement in `Cargo.toml`, then update that package and check your application.

```bash
cargo update -p proa_core
cargo proa check
```

With no file selection, `cargo proa check` checks template formatting, runs the lints, and checks the linked RSJS application. In a workspace, select the application with `-p <package> --bin <binary>`.

## Unreleased changes

Proa now requires Rust 1.98 or later; the previous minimum was 1.93.

The Axum adapter uses Axum 0.8. Routes registered directly on an `axum::Router`
must use `/{id}` and `/{*path}`; the `/:id` and `/*path` spellings panic when
the route is registered. Proa's declarative `Route` specs still accept both. Axum
0.8 also panics on `nest("/", ..)` and `nest_service("/", ..)`, so build a
router for `with_static_service` with `Router::new().fallback_service(..)`. See
[routing](/docs/framework/routing).

Applications using the React bridge should remove the `react` feature from their `proa` dependency and migrate `#[island]` components to RSJS. The workspace removes `proa_react` and the TSX attribute macro. See [RSJS islands](/docs/guides/islands).

## Using the 0.4 facade from source

The 0.4 framework facade is available from the Proa Labs repository. The published [`proa` 0.1.3](https://crates.io/crates/proa/0.1.3) is a Kubernetes utility. Select the Proa Labs Git source in your manifest and keep the resolved revision in your application's `Cargo.lock`.

```toml
[dependencies]
proa = { git = "https://github.com/Proa-Labs/proa.git", features = ["axum"] }
```

Import common types and macros from `proa::`, loaders from `proa::stream`, and
Axum integration from `proa::axum`. Enable `actions` for action data and derives.
RSJS and build-time font dependencies retain their own package versions.
Direct implementation-crate dependencies remain supported for advanced uses.

Managed metadata uses `render_head`, explicit Page/Layout roles, and a head
outlet. Markdown macros use one string body, and `content_part!` wrappers are
removed. Review which outgoing URLs need the application mount and use
`cx.url(path)` for those. See [metadata](/docs/framework/metadata),
[Markdown](/docs/core/markdown), and [rendering responses](/docs/framework/responses).

## Upgrading to 0.3

The 0.3 release moved the compiled-template framework into a standalone workspace. See the [0.3 migration guide](https://github.com/proa-labs/proa/blob/main/docs/migrations/0.3-standalone.md).

| Change | What to do |
|---|---|
| Standard render buffer | Replace bespoke writers with `RenderBuffer`. See [WriteBuf](/docs/core/write-buf) |
| Component-tree ownership moved | Components take ownership of children rather than borrowing |
| Native-mobile surface removed | No replacement. The crate no longer targets it |
| Runtime-template and `Vm*` surface removed | Templates are compile-time only. Move dynamic templates to data-driven components |
| Documentation-build adapters removed | Use `proa_docs_build`. See [Proa Docs](/docs/proa-docs) |
| Product-specific route codegen removed | Author routes directly. See [Routes and layouts](/docs/framework/routing) |

## Upgrading past 0.3

Breaking changes since 0.3 affect how components are authored and linked, how fonts are declared, and how Markdown components receive their context:

- **`#[proa_component]` is gone**, along with the inherent `#[rsjs(component)]` shorthand and RSJS `async fn render` sugar. Author `WebRenderSync` or the canonical `WebRender` signature directly, then apply `#[rsjs(component)]` for composition or `#[rsjs(component, client)]` when the component originates browser work. See [HTML rendering](/docs/core/html-rendering).
- **Component-level `clients(...)` allowlists are gone.** A reachable call to a `#[rsjs::client]` helper now creates a linker edge automatically. `#[rsjs::client_module]` remains as optional grouping. See [Client helpers](/docs/rsjs/client-helpers).
- **Deployable RSJS binaries require the linked `cargo proa` pipeline.** `cargo check` and rust-analyzer still give provisional type checking, but `cargo build` on an RSJS application now fails at link time with an actionable diagnostic instead of quietly producing a provisional binary.
- **`cargo proa font add` / `font remove` and `proa-fonts.toml` are gone.** Declare fonts in code with `google_font!` / `local_font!`; a `build.rs` collector vendors them and records `proa-fonts.lock`. `cargo proa font sync` runs the same collector outside a build. See [Fonts](/docs/framework/fonts).
- **`MdContext` is gone.** `MdRenderSync` and `MdRender` now take the same `WebContext<L, B>` as the HTML traits, with the loader first and no lifetime parameters, and Markdown helpers are named `md_*` / `write_md_*`. See [Markdown](/docs/core/markdown) and the [migration guide](https://github.com/proa-labs/proa/blob/main/docs/migrations/web-context.md).
- **`RouteResponse` is an opaque deferred-render plan** and `Layout` carries metadata only; the crate is `proa_framework_axum`. See [Responses](/docs/framework/responses) and the changelog for the smaller entries (event-handler parameters, `RenderOptions`, `mdx!`, client IR v3).
- **Managed metadata uses component roles and head hooks.** Select one `ROLE = PAGE`, mark ancestor metadata layouts as `LAYOUT`, and place one `{cx.head()}` outlet in the document. Async hooks use native `async fn render_head(...) -> Result<(), WriteError>`. The former `head()` inspection getter is `head_state()`; mutations go through the checked `head_mut()` writer. Enable managed mode with `FrameworkBuilder::with_head(...)`, or use `.without_head()` while migrating a manual document. See [Metadata](/docs/framework/metadata).
- **`FrameworkBuilder::new()` and `RouteContextLayer::new(metadata)` take no manifest, and the manifest-driven React island bootstrap is gone.** Removed: `IslandManifest` and its entry types, `RouteResponse::with_islands` and `with_bootstrap`, `render_bootstrap_for_islands`, `css_asset_path`, `render_css_link`, and the router's `Extension<Arc<IslandManifest>>`. The finalizers (`finalize_route_response*`, `render_*_html_response`, `into_framework_response`) lose their manifest parameter. Link a stylesheet from the layout with `cx.url(..)`. `RouteResponse::render_to_bytes` renders a finalized document with no server or runtime. See [Configuration](/docs/framework/configuration) and [Route responses](/docs/framework/responses#rendering-without-a-server).
- **Application URL composition now lives on `cx.url(path)`.** Move outgoing URL construction off `cx.request()`. The helper explicitly applies the configured base path and writes directly into HTML attributes or Markdown links; plain URL strings stay unchanged. See [Linking](/docs/framework/linking).
- **Project configuration moved from `proa.config.json` to `proa.config.rs`.** Export `pub async fn config() -> Result<Config>` returning a `proa::config::Config` literal. Run configured lifecycle scripts with `proa run dev` and `proa run build`; `proa dev` and `proa build` enter the built-in workflows directly. Managed public assets are enabled for `public/` by default via `PROA_PUBLIC_ASSETS` and `cx.url("public/...")`. `FrameworkBuilder::try_build()` now returns `Result<Router, FrameworkBuildError>`. See [proa.config.rs](/docs/framework/project-config) and [Static assets](/docs/framework/static-assets#managed-public-assets).
- **The unused legacy effect IR and fluent expression builder are gone.** Browser effects use RSJS. The `proa_ir` expression/value model, bounded evaluator, reactive bindings, and component trees remain available.
- **The deprecated pool-backed writers are gone.** Replace `SinkWriter`, `SinkPage`, `PagePool`, `MemorySink`, their in-order aliases, and `SinkCheckpoint` with `RenderBuffer` and its checkpoints. Custom transport adapters keep using `StreamChunkFlusher` / `SendStreamChunkFlusher`. See [WriteBuf](/docs/core/write-buf).
- **The file-backed action collision checker is gone.** Remove calls to `proa::actions::check_action_collisions` and `clear_action_registry`, and imports from `collision_check`. The action derive never populated that registry. Scoped action names and the action data/code generation APIs remain available.
- **The standalone `proa_codegen` crate and `proa-codegen` binary are gone.** Component libraries own their metadata-to-TypeScript generation; Proa UI has its own generators. `proa new site` continues to use the CLI's site scaffolder.
- **The old `proa_cli::scaffold::new_site` Rust API is gone.** Use the `proa new site` command, which uses `site_scaffold`. The component, layout, and data generators remain available.
- **Generators no longer add placeholder render or source-text tests.** The page, endpoint, and component generators no longer accept `--no-test`. ORIGIN keeps its loader and runtime integration tests without a full-page HTML snapshot.
- **The unused `ProaConfig` API is gone**, including `PathsConfig`, `CodegenConfig`, `ServerConfig`, and `FrameworkBuilder::{with_config, config}`. Those values did not affect the router. Mount assets with `with_static_service`, configure middleware through the builder, and bind your listener to select the host and port. See [Configuration](/docs/framework/configuration).
- **Unused framework side features are gone:** `ExternalApp`, `ExternalAppStrategy`, `FrameworkBuilder::with_external_app`, the `proxy`, `process_manager`, and `shard` modules, and the `route-export` feature/module. Compose static applications through Axum's router APIs and manage upstream processes and proxies in your deployment. Route `PageCache` and the generic readiness probes remain available.
- **Unused compatibility helpers are gone.** Use `RenderBuffer` instead of `DefaultChainedBumpWriter`, `load_json*` / `load_typed*` instead of the deprecated context `load*` aliases, and `drain_pending_boundaries_with_artifacts` or `drain_pending_boundaries_with_nonce_and_artifacts` for deferred streaming output. Use `[u8; N]` or `SmallBuf<N>` directly instead of the fixed-size aliases in `stack`; construct a `WebContext` with your writer instead of `render_into_vec_with_hint`.

> **Good to know**: The linked-pipeline change is the one most likely to surprise CI. If your pipeline runs `cargo build`, switch it to `cargo proa build`. See [CI / GitHub Actions](/docs/guides/ci).

## When an upgrade breaks the build

- Run `cargo proa check` from the application directory to capture template and RSJS linker diagnostics.
- If a render trait no longer compiles, compare its signature with the [rendering reference](/docs/core/html-rendering). For the Markdown context change, follow the [shared WebContext migration](https://github.com/proa-labs/proa/blob/main/docs/migrations/web-context.md).
- Look up the diagnostic in [Troubleshooting](/docs/guides/troubleshooting).
