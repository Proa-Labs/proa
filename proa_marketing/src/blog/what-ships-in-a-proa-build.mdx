A Proa build brings together files from several places. Your stylesheet and images come from the application, while the RSJS runtime and island modules come from the linked build. The exported asset bundle gives them one place to live.

## Deploy the executable with its assets

Run `proa build` to build the executable and publish the asset bundle beside it. The bundle includes the linked RSJS modules, the stylesheet, and other published files. Deploy the executable and the adjacent `.assets` directory together so the server can load the matching catalog at startup.

The immutable asset paths carry content fingerprints. When a file changes, its URL changes with it. Fixed root files such as a favicon can keep the paths browsers expect.

## Serve the same files from a static host

The bundle stores published files at their URL paths. A static host can serve the same asset bytes while the application server handles requests that need a rendered response. The catalog lets the server verify and link the files from the same build.

The [deployment guide](/docs/framework/deployment) walks through packaging and serving the result. [Pull request #101](https://github.com/Proa-Labs/proa/pull/101) explains how the layout came together.
