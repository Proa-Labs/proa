---
title: proa generate
description: Generate pages, endpoints, models, migrations, components, layouts, and data modules.
---

The generator commands write files into an existing Proa project. By default, they use the nearest parent project directory. Pass `--root` when running from outside the project tree.

## Pages

```bash
proa generate page about
proa generate page blog/{slug}
```

This writes `src/pages/<module>.rs` with a page component and its `handler`, adds the module to `src/pages/mod.rs`, and registers the route in `src/routes.rs`. Nested segments join into one module name: `blog/{slug}` becomes `src/pages/blog_slug.rs`. `:slug` and `*rest` segments are accepted and registered as `{slug}` and `{*rest}`.

When the project has Markdown representations (`proa add representation markdown`), the page also serves Markdown at `<path>.md` and through [content negotiation](/docs/framework/content-negotiation).

| Flag | Behavior |
|------|----------|
| `--markdown` | Require the Markdown representation; fails if the project does not have it. |
| `--no-markdown` | Generate an HTML-only page in a Markdown-enabled project. |
| `--root <DIR>` | Use an explicit project root. |
| `--dry-run` | Print the plan without writing. |
| `--json` | Print the plan or result as JSON. |

The command fails if the page file already exists or the route is already registered.

## Endpoints

```bash
proa generate endpoint api/contact --method post --response json
```

This writes `src/endpoints/api_contact.rs` with a `handler`, adds the module to `src/endpoints/mod.rs`, and registers `POST /api/contact` in `src/routes.rs`.

| Flag | Behavior |
|------|----------|
| `--method <METHOD>` | Required. `get`, `post`, `put`, `patch`, or `delete`. |
| `--response <KIND>` | Required. `json`, `redirect`, `empty` (204 No Content), or `html`. |
| `--root <DIR>` | Use an explicit project root. |
| `--dry-run` | Print the plan without writing. |
| `--json` | Print the plan or result as JSON. |

## Models

```bash
proa generate model product name:text price_cents:integer sku:text:unique
```

This writes `src/models/product.rs` with a `sqlx::FromRow` struct (`id`, your fields, `created_at`, and `updated_at`), adds it to `src/models/mod.rs`, and writes a `create_products` up/down migration pair. Models and migrations require the SQLite capability from `proa add database sqlite`.

Each field is `name:type[:modifier...]`:

| Type | Rust type | SQLite column |
|------|-----------|---------------|
| `text`, `string` | `String` | `TEXT` |
| `integer`, `bigint` | `i64` | `INTEGER` |
| `real` | `f64` | `REAL` |
| `boolean` | `bool` | `INTEGER` |
| `blob` | `Vec<u8>` | `BLOB` |
| `datetime`, `uuid` | `String` | `TEXT` |

| Modifier | Effect |
|----------|--------|
| `optional` | `Option<T>` field and a nullable column. |
| `unique` | `UNIQUE` column. |
| `default=<SQL>` | `DEFAULT <SQL>` column. |
| `references=<model>` | Foreign key to `<model>s(id)`. |

`--root`, `--dry-run`, and `--json` work as they do for pages.

## Migrations

```bash
proa generate migration add_sku_to_products
proa db migrate
```

This writes an up/down pair numbered one past the highest existing migration, such as `migrations/0002_add_sku_to_products.up.sql` and `migrations/0002_add_sku_to_products.down.sql`. Fill in both files; Proa does not guess the inverse SQL.

| Flag | Behavior |
|------|----------|
| `--simple` | Write one irreversible `.sql` file instead of an up/down pair. |
| `--open` | Open the new files with `$VISUAL` or `$EDITOR`. |
| `--root <DIR>` | Use an explicit project root. |
| `--dry-run` | Print the plan without writing. |
| `--json` | Print the plan or result as JSON. |

## Components

```bash
proa generate component pricing/feature-row --children --recipe
```

This creates module entries under `src/components` and writes either a single component file or a component folder. Generators do not add placeholder tests; add a test when the component has behavior worth protecting.

| Flag | Behavior |
|------|----------|
| `--folder` | Use `components/<name>/mod.rs` plus a sibling implementation file. |
| `--recipe` | Generate `recipe.rs` and a folder layout. |
| `--children` | Add generic `children` support. |
| `--async` | Implement `WebRender` instead of `WebRenderSync`. |
| `--markdown` | Add an `MdRenderSync` implementation. |
| `--root <DIR>` | Use an explicit project root. |
| `--dry-run [text\|json]` | Print the plan without writing. |
| `--force` | Overwrite generated files. |

Names can include folders. `pricing/feature-row` becomes `src/components/pricing/feature_row.rs` or a folder-backed component when `--folder` or `--recipe` is used.

## Layouts

```bash
proa generate layout marketing-shell --section
proa generate layout root-document --document
```

| Flag | Behavior |
|------|----------|
| `--section` | Generate a section-level wrapper. |
| `--document` | Generate a full document shell. |
| `--replace-root` | With `--document`, move the document-root marker from the current root layout to the new one. |
| `--root <DIR>` | Use an explicit project root. |
| `--dry-run [text\|json]` | Print the plan without writing. |
| `--force` | Overwrite generated files. |

`--document` and `--section` cannot be combined.

Generated wrappers use manual rendering. For a managed document, add the head
outlet to the document shell and declare `ROLE = LAYOUT`; its selected Page
declares `ROLE = PAGE`. Body-only visual wrappers keep the default `COMPONENT`
role. See [Layouts and Pages](/docs/framework/layouts-and-pages).

## Data Modules

```bash
proa generate data pricing-plans
```

Data modules are written under `src/static_data` and registered in the nearest module file.

## Module Updates

Generators append missing `pub mod ...;` lines to parent `mod.rs` files. Existing matching lines are left in place, so repeated dry runs and repeated generation do not duplicate module exports.

## Safety Workflow

Use this pattern when generating into a project with local edits:

```bash
proa generate component pricing/feature-row --children --recipe --dry-run
proa generate component pricing/feature-row --children --recipe
cargo fmt --all
proa test
```

Only use `--force` when you intend to replace generated files.
