During development, the Axum adapter relays the browser's live-reload connection to a local event server. The relay needs to open an HTTP/1 connection, forward the response as a stream, and close the connection when the browser disconnects.

## Reuse the HTTP stack

The relay previously used Reqwest. That brought a second client layer and a TLS stack into applications even when they only used the client for this localhost connection. The adapter already used Hyper and Tokio, so the relay now uses Hyper's HTTP/1 client over a Tokio TCP stream.

The new path keeps a connect timeout and ties upstream connection cleanup to the lifetime of the response body. Development requests can still stream without buffering the event feed.

## What changed in the build

In an Apple Silicon release build of a small standalone Axum application, the normal dependency graph went from 261 to 243 packages. The release binary went from 13.56 MiB to 9.27 MiB. Those numbers describe the sample app and its thin-LTO build profile. An application with its own HTTPS client will have a different footprint.

The implementation and measurements are in [pull request #113](https://github.com/Proa-Labs/proa/pull/113). See the [live reload guide](/docs/cli/new-site#live-reload) to try the development workflow.
