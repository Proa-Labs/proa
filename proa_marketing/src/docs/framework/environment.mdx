title: Environment variables
description: Configure a deployed Proa app without rebuilding the binary.

One release binary runs in every environment. Read bind address, origin, and secrets once at startup; managed public assets load automatically from `app.assets/` beside the binary:

```rust filename="src/config.rs"
use std::{env, net::{IpAddr, SocketAddr}};

#[derive(Clone, Debug)]
pub struct RuntimeConfig {
    pub bind: SocketAddr,
    pub public_base_url: Option<String>,
    pub trusted_origin: Option<String>,
}

impl RuntimeConfig {
    pub fn from_env() -> anyhow::Result<Self> {
        let host: IpAddr = env::var("PROA_HOST")
            .or_else(|_| env::var("HOST"))
            .unwrap_or_else(|_| "127.0.0.1".into())
            .parse()?;
        let port: u16 = env::var("PORT")
            .ok()
            .map(|v| v.parse())
            .transpose()?
            .unwrap_or(3000);
        Ok(Self {
            bind: SocketAddr::new(host, port),
            public_base_url: optional_env("PUBLIC_BASE_URL"),
            trusted_origin: optional_env("TRUSTED_ORIGIN"),
        })
    }
}

fn optional_env(name: &str) -> Option<String> {
    env::var(name).ok().filter(|v| !v.trim().is_empty())
}
```

## Defining the runtime contract

Keep the contract small and explicit:

| Variable | Required | Use |
|----------|----------|-----|
| `PROA_HOST` | No | Bind host (`0.0.0.0` in containers, `127.0.0.1` behind a same-host reverse proxy). `proa start --host` sets this. |
| `PORT` | No | Bind port. Container platforms often inject this. |
| `PROA_PUBLIC_ASSETS` | No | Overrides where `FrameworkBuilder::try_build()` loads the public asset catalog mounted at `/_proa/immutable` and `/_proa/mutable`. Unset, the server loads `app.assets/` beside its executable. |
| `PROA_ASSET_PREFIX` | No | URL the bundle's `public/` directory was uploaded to, such as `https://cdn.example.com/site`. When set, `cx.url("public/...")`, font URLs, and bundled RSJS module URLs start with it instead of the base path. Read at startup; ignored under `proa dev`. See [serving assets from a static host](/docs/framework/deployment#serving-assets-from-a-static-host). |
| `RUST_LOG` | No | `tracing_subscriber` filter, usually `info` in production. |
| `PUBLIC_BASE_URL` | Usually | Absolute origin for metadata, canonical URLs, emails, and webhooks. |
| `TRUSTED_ORIGIN` | If needed | Browser origin allowed to send unsafe cross-origin requests. |
| `DATABASE_URL` | If needed | Database connection string or pool configuration input. |

Do not reach for a runtime variable where render code wants a compile-time constant. Pass runtime values through handlers, app state, loaders, or explicit props.

## Loading config once

Load `RuntimeConfig` once in `main`:

```rust filename="src/main.rs"
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    tracing_subscriber::fmt::init();

    let config = RuntimeConfig::from_env()?;
    let app = build_app(config.clone())?;

    let listener = tokio::net::TcpListener::bind(config.bind).await?;
    tracing::info!("listening on http://{}", listener.local_addr()?);
    proa::axum::serve(
        listener, app, std::time::Duration::from_secs(30),
    ).await?;

    Ok(())
}
```

That config value then travels to exactly one place: the application boundary.

## Applying config to FrameworkBuilder

Use runtime config where you build the router. `try_build()` loads `app.assets/` (or `PROA_PUBLIC_ASSETS`) and applies `PROA_ASSET_PREFIX` automatically:

```rust filename="src/app.rs"
use axum::Router;
use proa::axum::FrameworkBuilder;

pub fn build_app(config: RuntimeConfig) -> anyhow::Result<Router> {
    let (routes, metadata) = build_routes();

    let mut builder = FrameworkBuilder::new()
        .with_dynamic_routes_and_metadata(routes, metadata);

    if let Some(origin) = config.trusted_origin.as_deref() {
        builder = builder.with_trusted_origin(origin);
    }

    Ok(builder.try_build()?)
}
```

Configure discovery endpoints from these typed startup values:

```rust filename="src/main.rs" {13-14}
use proa::BasePath;
use proa::axum::{FrameworkBuilder, RobotsTxt, SitemapUrl};

let config = RuntimeConfig::from_env()?;
let origin = config.public_base_url.as_deref().unwrap_or("http://localhost:3000");
let base_path = BasePath::new(
    &std::env::var("PROA_BASE_PATH").unwrap_or_default(),
)?;

let app = FrameworkBuilder::new()
    .with_base_path(base_path)
    .with_public_origin(origin)?
    .with_sitemap([SitemapUrl::new("/")?])
    .with_robots(RobotsTxt::new().allow("/")?)
    .try_build()?;
```

Optional values tolerate a fallback like this one. Secrets do not.

## Handling required secrets

Fail fast for required secrets:

```rust filename="src/config.rs"
fn required_env(name: &'static str) -> anyhow::Result<String> {
    let value = env::var(name).map_err(|_| anyhow::anyhow!("{name} must be set"))?;
    anyhow::ensure!(!value.trim().is_empty(), "{name} must not be empty");
    Ok(value)
}

let database_url = required_env("DATABASE_URL")?;
let stripe_secret_key = required_env("STRIPE_SECRET_KEY")?;
```

Read secrets in startup code or request handlers. Do not read them inside `WebRenderSync` implementations, and do not pass secrets into page props.

Some variables never reach the running process at all, because the build consumes them first.

## Separating build-time from runtime

Keep these separate:

| Variable | Phase | Notes |
|----------|-------|-------|
| `PROA_VERSION` | Build | Pins the CLI installed by the Dockerfile or CI installer. Public Proa dependencies require no GitHub credential or registry token. |
| `STATIC_DIR` | Runtime | Points the running server at public assets. |
| `DATABASE_URL` | Runtime | App startup or handlers read it. |
| `PUBLIC_BASE_URL` | Runtime | Safe to expose only if you explicitly render it. |
| `RUST_LOG` | Runtime | Controls logs without rebuilding. |

If a variable changes how Rust code compiles, use Cargo features or build-time configuration. If it changes how one deployed artifact runs, use a runtime environment variable.

Runtime variables stay on the server unless you render them yourself.

## Exposing values to the browser

Proa never copies environment variables into the browser on your behalf. Whitelist values explicitly:

```rust filename="src/layouts/root.rs"
pub struct PublicConfig {
    pub base_url: &'static str,
    pub analytics_enabled: bool,
}

html_sync! {
    <meta name="app-base-url" content={public_config.base_url} />
    <meta
        name="analytics-enabled"
        content={if public_config.analytics_enabled {
        "true"
    } else {
        "false"
    }}
    />
}
```

Render a value only when it can safely appear in page HTML, view source, logs, caches, and browser devtools.

Locally, the same variables come from your shell instead of a platform dashboard.

## Working locally

Use shell exports or a local `.env` loader:

```bash filename="Terminal"
HOST=127.0.0.1 PORT=3000 RUST_LOG=debug proa run
```

```rust filename="src/main.rs"
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    #[cfg(debug_assertions)]
    let _ = dotenvy::dotenv();

    let config = RuntimeConfig::from_env()?;
    // build and serve the app
    Ok(())
}
```

Keep `.env` out of git. Generated Proa projects already ignore `.env`.

> **Good to know**: `dotenvy::dotenv()` sits behind `#[cfg(debug_assertions)]`, so the `.env` loader compiles out of any build with debug assertions off.

In production, the platform supplies the same values through the container or the service unit.

## Setting variables in production

Set runtime variables on the container, not in the image:

```bash filename="Terminal"
docker run --rm \
  -p 3000:3000 \
  -e HOST=0.0.0.0 \
  -e PORT=3000 \
  -e STATIC_DIR=/app/public \
  -e RUST_LOG=info \
  -e PUBLIC_BASE_URL=https://example.com \
  hello-proa
```

For Cloud Run and similar platforms, set `HOST=0.0.0.0`, read the injected `PORT`, and configure secrets through the platform secret manager.

A systemd unit carries the same contract:

```ini filename="/etc/systemd/system/hello-proa.service"
[Service]
Environment=HOST=127.0.0.1
Environment=PORT=3000
Environment=STATIC_DIR=/opt/hello-proa/public
Environment=RUST_LOG=info
Environment=PUBLIC_BASE_URL=https://example.com
ExecStart=/opt/hello-proa/bin/hello-proa
```

Use `EnvironmentFile=/etc/hello-proa/env` if you manage variables outside the unit file.
