# Proa 0.4.0

Proa 0.4.0 adds managed page metadata, simpler Markdown authoring, explicit
application URLs, and better reuse of linked compiler work. It also removes
experimental and deprecated APIs so the supported path is easier to follow.

This release contains breaking changes. The upgrade checklist below covers the
main application changes; keep the Proa libraries, RSJS, and CLI on compatible
release versions when upgrading.

## Page metadata

Pages and layouts can now contribute metadata through `render_head`, using the
same request context and loader as the body. Layouts provide defaults; the
selected page overrides the fields it needs. Titles, descriptions, canonical
URLs, Open Graph, Twitter cards, icons, robots directives, alternates, and other
metadata share one validated lifecycle.

Inside an existing `WebRender<L>` implementation, a page can define:

```rust
const ROLE: ComponentRole = ComponentRole::PAGE;

async fn render_head(&self, cx: &mut WebContext<L>) -> Result<(), WriteError> {
    cx.head_mut().title("Trail Jacket")?;
    cx.head_mut().description("Built for the outdoors.")?;
    cx.head_mut().canonical("/products/trail-jacket")?;
    Ok(())
}
```

Enable managed metadata with `RouteResponse::with_head` or
`FrameworkBuilder::with_head`, configure a trusted public origin, and place
`{cx.head()}` in the document's `<head>`. Layouts declare `ROLE = LAYOUT`; the
selected page declares `ROLE = PAGE`. Body-only components keep the default
`COMPONENT` role.

Bulk `HeadMetadata` values support inherit, set, and clear operations. Clearing
an inherited value is explicit with `HeadValue::Clear`; omitted fields retain
their inherited values. Metadata preparation finishes before the page body and
HTTP publication, including streaming responses.

The framework also supports validated sitemaps, sitemap indexes, and
`robots.txt`, with mount-aware URLs. Page robots metadata and `robots.txt`
remain separate controls.

See [metadata](https://proa.so/docs/framework/metadata),
[the metadata reference](https://proa.so/docs/framework/metadata-reference),
[sitemaps](https://proa.so/docs/framework/sitemaps), and
[robots.txt](https://proa.so/docs/framework/robots).

## Markdown and shared content

Author `md_sync!` and `md!` with a single string body. Multiline raw templates
preserve source newlines, strip ordinary Rust indentation, and compose typed
children through `{expression}` slots:

```rust
md_sync! { r###"
    # {self.title}

    {self.body}
    "###
}
```

Control flow inside a slot is Rust. Re-enter Markdown through a nested macro
when a loop or branch emits authored Markdown. Braces in fenced code blocks and
inline code spans stay literal.

Block and inline templates track their surrounding Markdown context, so block
children compose without manual spacing or heading-offset plumbing. `proa fmt`
and `proa lint` use the same layout rules.

HTML and Markdown can share their content through ordinary component fields.
The content-coverage linter now infers supported contributions from those
inputs; `content_part!` has been removed. The linter has limits and reports
unsupported coverage explicitly rather than requiring another authoring macro.

See [document authoring](https://github.com/Proa-Labs/proa/blob/main/docs/agent/document-rendering.md).

## RSJS and browser behavior

Application URL mounting is now explicit. Use `cx.url(path)` when a URL belongs
under the configured application base path. A plain `"/api/items"` keeps its
normal browser meaning and targets the origin root. Queries and mutations
recognize the same opt-in, so applications mounted at paths such as `/shop`
can use mount-aware endpoints without rewriting every root-relative URL.

The linked build pipeline now reuses cached descriptors and per-unit plans
across warm builds. Compiler orchestration and source tools have moved into
separate support crates, keeping those engines out of the CLI's main source
modules. There are also fixes for linked lookups, unused components, and
Windows builds.

Continue to use `cargo proa build` for deployable RSJS applications. Ordinary
`cargo check` provides editor and type-checking feedback; it does not replace
final linking.

See [RSJS authoring](https://github.com/Proa-Labs/proa/blob/main/docs/agent/rsjs-islands.md).

## Rendering and framework integration

`RenderBuffer` is the standard reusable output buffer. Deprecated page-pool
writers and compatibility aliases have been removed. Keep ordinary routes on
`RouteResponse::ssr`, `ssr_async`, or `ssr_stream`.

`RouteResponse::render_to_bytes` and `render_to_string` finalize a document from
synchronous code without starting an HTTP server. They support managed metadata
and RSJS finalization; async plans finish as buffered output. Use the HTTP path
when rendering depends on actual request context, and await the framework
response API from async code.

Outgoing application URLs use `cx.url(path)` to apply the configured base path.
Plain URL attributes retain their authored meaning. The adapter crate is
`proa_framework_axum`; `proa_framework_core` remains the portable contract.

The framework now defaults the island manifest, reducing manual setup for pages
with islands. Managed head preparation integrates with buffered and streaming
responses, including cancellation and error handling before publication.

See [route responses](https://proa.so/docs/framework/responses) and
[data loading](https://proa.so/docs/framework/data-loading).

## CLI and generated projects

Install the CLI and create a project:

```sh
cargo install proa-cli --version 0.2.0 --locked
proa new site my-site
```

`proa new site` generates projects with crates.io dependencies. Scaffold versions
are derived from Cargo declarations, and the release workflow publishes libraries
before checking all five generated templates against the registry. The CLI is
published only after those standalone checks pass.

`proa update` understands how the CLI was installed and updates versioned
standalone bundles. Source builds and generated projects use crates.io. Live
lint diagnostics are available through the editor/LSP integration.

The release also retires experimental form builders, placeholder email APIs,
the standalone TypeScript generator, and unused deployment/proxy surfaces.
Proa remains licensed under Apache-2.0.

## Upgrade checklist

1. Update the coordinated Proa libraries to `0.4`, RSJS dependencies to their
   compatible `0.3` releases, and the CLI to `0.2.0`. Ancillary crates retain
   their own version series; a fresh generated project provides the supported
   dependency set.
2. For managed metadata, add the head outlet, configure `HeadConfig`, and declare
   `PAGE` / `LAYOUT` roles. Replace legacy head mutation with checked
   `cx.head_mut()` setters. Keep manual documents outside managed mode with
   `.without_head()` where appropriate.
3. Replace inspection through `cx.head()` with `cx.head_state()`;
   `cx.head()` now returns the renderable outlet. Bulk metadata uses explicit
   `HeadValue` inherit/set/clear values.
4. Migrate Markdown macros to one string body and remove heading-offset and
   manual formatting-state plumbing. Remove `content_part!` wrappers and let
   the coverage linter inspect ordinary shared inputs.
5. Replace `RequestContext::url` with `cx.url(path)` and review which browser
   requests should opt into the application mount. Plain root-relative URLs
   intentionally continue to target the origin root.
6. Replace removed loader conveniences with typed or explicit loader access,
   deprecated writer aliases and page-pool writers with `RenderBuffer`, and
   byte-only boundary drains with artifact-preserving streaming APIs.
7. Remove dependencies on retired form builders, placeholder email APIs,
   `proa_codegen`, and the unused external-app/proxy/deployment surfaces.
8. Rebuild the application and its RSJS dependencies together, then run
   formatting, lint, application tests, and `cargo proa build`.

The workspace requires Rust 1.93 or newer. Read the compiler's migration errors
alongside the [agent documentation](https://github.com/Proa-Labs/proa/tree/main/docs/agent)
and the [framework guides](https://proa.so/docs/framework/metadata).
