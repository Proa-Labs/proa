description: Generate request-aware titles, descriptions, and social preview images.

Layouts and pages provide metadata for each request. Providers can read route
params, search params and headers, load data through the page's loader, and
extend their parent's metadata. Proa resolves the result before rendering the
document head, including for streamed responses.

## Title-only pages

`Route::page` creates metadata that can be precomputed:

```rust
Route::page("/pricing", "Pricing", get(pricing))
```

## Static metadata

Implement `static_metadata` for values that never depend on the request or
parent. Layouts implement `Metadata` as well as `Layout`:

```rust
use proa_framework_axum::{CascadeValue, Metadata, MetadataPatch};

impl Metadata for AppLayout {
    fn static_metadata(&self) -> Option<MetadataPatch> {
        Some(MetadataPatch {
            title: CascadeValue::Set("%s - My Site".into()),
            description: CascadeValue::Set("A Proa application.".into()),
            ..Default::default()
        })
    }
}
```

Literal strings stay borrowed. Proa precomputes the static prefix of each
route's provider stack and resolves the rest per request.

## Request-aware metadata

Write a plain async function. It can complete immediately when it only needs
request inputs:

```rust
use proa_framework_axum::{CascadeValue, MetadataContext, MetadataPatch, MetadataResult};

async fn search_metadata(cx: MetadataContext) -> MetadataResult {
    let query = cx.search_params()
        .find(|(key, _)| key == "q")
        .map(|(_, value)| value.into_owned())
        .unwrap_or_default();

    Ok(MetadataPatch {
        title: CascadeValue::Set(format!("Search: {query}").into()),
        ..Default::default()
    })
}
```

`cx.param("slug")` reads a route param. `cx.search_params()` yields decoded
query pairs, preserving duplicate keys. `cx.request()` exposes headers, cookies,
location and the configured base path.

## Generated metadata and shared data

The same function API supports data loading:

```rust
use proa_core::LoadKey;
use proa_framework_axum::{CascadeValue, MetadataContext, MetadataPatch, MetadataResult};

#[derive(serde::Deserialize)]
struct Post {
    title: String,
    description: String,
}

async fn generate_metadata(cx: MetadataContext) -> MetadataResult {
    let slug = cx.param("slug").unwrap_or_default();
    let post: Post = cx.load_json(LoadKey::named("post", slug)).await?;
    Ok(MetadataPatch {
        title: CascadeValue::Set(post.title.into()),
        description: CascadeValue::Set(post.description.into()),
        canonical: CascadeValue::Set(format!("/blog/{slug}").into()),
        ..Default::default()
    })
}

let route = Route::page_with_metadata("/blog/:slug", get(post), &generate_metadata);
```

`MetadataResult` is an alias for `Result<MetadataPatch, MetadataError>`. The
framework registers the function directly; no provider struct, implementation
block, trait object, parent parameter or lifetime qualifier is needed.
`cx.parent()` gives access to the metadata inherited from earlier providers.

Return an async `RouteResponse` from `post` and install the page's loader with
`ssr_async_with_loader` or `ssr_stream_with_loader`. Metadata uses that same
loader instance. A fresh `proa_stream::DataResolver::new_typed` per response
deduplicates metadata and page loads with the same key. `load_typed` shares an
already-materialized `Arc<T>`; JSON and bytes are supported too.

If the page is synchronous but metadata needs to await data, lift the page
with `proa_core::to_async(page)` and use an async response constructor. A
synchronous response can resolve a generator that completes immediately; if
it suspends, it returns `AsyncInSyncResponse`.

The context owns shared handles to the existing request and loader. Request
headers and params are not copied for each function. The framework handles
future erasure when storing heterogeneous route providers; application code
uses ordinary `.await` and `?`.

## Local metadata futures

Ordinary async metadata functions can serve both local and Send responses.
If a function retains non-Send state across an await, register it through
`local_metadata`:

```rust
use proa_framework_axum::local_metadata;

let route = Route::page_with_metadata(
    "/blog/:slug",
    get(post),
    local_metadata(local_post_metadata),
);
```

`local_post_metadata` has the same `(MetadataContext) -> MetadataResult`
async signature. These functions work with local async responses; Send
responses reject them before rendering with `LocalInSendResponse`. Register
once while building the route tree. The adapter also works as a metadata
layout for a group of routes.

## Deployment URLs

Configure a base from deployment settings so relative URLs work on staging
and production:

```rust
use proa_framework_axum::MetadataBase;

let metadata_base = MetadataBase::new(&std::env::var("PUBLIC_URL")?)?;
let app = builder.with_metadata_base(metadata_base).build();
```

For `PUBLIC_URL=https://staging.example/app/`, `/blog/post` resolves to
`https://staging.example/app/blog/post`. Include the public mount prefix in an
explicit base. Absolute HTTP(S) URLs remain unchanged. Canonical and all Open
Graph media URLs use the same resolution rules.

A provider may set `MetadataPatch::metadata_base`. Request middleware may
instead supply a validated `MetadataBase` in request extensions. Without an
explicit base, an absolute request URI supplies its origin plus `BasePath`.
Origin-form requests have no scheme, so relative URLs require a configured
base; Proa does not infer HTTPS from `Host` or forwarding headers.

The final provider's base takes precedence over the request extension, which
includes the deployment default. When configuring the route context layer
directly, use `RouteContextLayer::with_metadata_base` for that default.

Both `/og.png` and `og.png` resolve within the configured base directory.
Protocol-relative URLs use the base's scheme; dot segments, query-only and
fragment-only references follow URL joining rules. Bases must be absolute
HTTP(S) URLs without credentials, a query or a fragment.

## Parent values and lists

`Unset` inherits and `Tombstone` clears. `Set` replaces, including lists. To
append an image, explicitly extend the parent's images:

```rust
use proa_framework_axum::{OpenGraphPatch, ResolvedOpenGraphImage};

let mut images = cx.parent().open_graph.images.to_vec();
images.push(ResolvedOpenGraphImage::new("/post-preview.png"));

MetadataPatch {
    open_graph: OpenGraphPatch {
        images: CascadeValue::Set(images.into()),
        ..Default::default()
    },
    ..Default::default()
}
```

Parent values reflect earlier providers in the cascade. URL references are
normalized after the final patch so the final metadata base applies to the
whole document.

`Set` with an empty list clears the list. Title templates use `%s`; setting
`MetadataPatch::absolute_title` bypasses and clears the inherited title
template. A title tombstone clears its template too, so later values cannot
restore a removed title through that template.

## Rendering the head

Axum's head helper supports any loader and writer:

```rust
fn render_head<L: proa_core::DataLoader, B: proa_core::WriteBuf>(
    cx: &mut proa_core::WebContext<L, B>,
) {
    proa_framework_axum::render_metadata_head(cx);
}
```

Use `render_metadata_head_send` for `SendWebContext`. To inspect the result in
a local component, use `metadata_from_context(cx)`. Resolved metadata travels
with the request into deferred streams and boundaries. Client-navigation
responses use the generated title from that same resolution.

Metadata finishes before body bytes are sent in both streaming modes. A
metadata error at that point can therefore become an HTTP error response.
For cached pages, metadata that depends on headers needs matching cache
variation or a private/no-store response, just like request-dependent content.

## Migrating existing metadata

1. Existing `title`, `description` and `open_graph` getters remain supported.
   Use async functions returning `MetadataResult` for new request-aware
   metadata. Old getter providers resolve per request until they explicitly
   implement `static_metadata`; `Route::page` opts into static precomputation
   automatically.
2. Resolved text fields, including Open Graph media text, now use
   `Cow<'static, str>`. Construct values with `.into()` and borrow optional
   text with `.as_deref()`. Use `OpenGraphPatch` for dynamic metadata;
   `CascadeOpenGraph`, `OpenGraph`, `OpenGraphImage` and `OpenGraphMedia`
   remain compatibility descriptors.
3. Lists now replace on `Set` rather than implicitly appending. To preserve
   parent entries, explicitly extend the parent's list as shown above.
4. `ComputedRouteMeta` is a resolution plan rather than a public struct
   literal. Construct it with `cascade`; call `resolve_sync`, `resolve` or
   `resolve_send` with shared request and loader `Arc`s. Custom provider storage
   uses `MetadataRef` or `DynMetadata`; static or stateful providers can still
   implement `Metadata`. Dereferencing the plan and calling
   `resolved_metadata_from_computed` expose only its precomputed static prefix.
5. Inside components, use `metadata_from_context(cx)` to read the resolved
   result. The legacy no-argument `resolved_metadata()` accessor can only run
   immediate providers without a loader; it cannot support async generation
   or deferred rendering. The request-free `resolve_metadata_stack` helper
   only considers legacy getters and explicitly static patches, leaving URL
   references unnormalized.
