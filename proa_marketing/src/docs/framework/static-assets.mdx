Proa supports both managed public assets published by the CLI under `/_proa/immutable` and `/_proa/mutable` and custom static routers nested at `/static` through `FrameworkBuilder`. Reference a managed file in a template by its logical `public/...` path with `cx.url(...)`:

```rust filename="src/layouts/root.rs"
let favicon = cx.url("public/favicon.svg");
let stylesheet = cx.url("public/styles.css");

html_sync! {
    <link rel="icon" href={favicon} />
    <link rel="stylesheet" href={stylesheet} />
}
```

This page covers [managed public assets](#managed-public-assets), [disk-backed assets](#serving-assets-from-disk), [embedded assets](#embedding-assets-in-the-binary), [linked island assets](#serving-linked-island-assets), [linking stylesheets](#linking-the-application-stylesheet), and [external apps](#mounting-external-apps).

## Managed public assets

By default, `proa build`, `proa dev`, `proa run`, and `proa test` publish `public/` into a verified asset catalog. `proa dev`, `proa run`, and `proa test` pass its path to the app through `PROA_PUBLIC_ASSETS`; `proa build --artifact-out <path>` writes it beside the exported executable, where the app finds it on its own. `FrameworkBuilder::try_build()` loads that catalog automatically and mounts its routes under `/_proa/immutable` and `/_proa/mutable`.

Templates reference those files by logical path, as in the example at the top of this page.

The same `cx.url(...)` call works directly inside Markdown (`MdRenderSync` / `MdRender` with `md_sync!` / `md!`) and preserves query strings, fragments, and deployment base paths:

```rust filename="src/pages/home.rs"
md_sync! { r###"
    ![Brand]({cx.url("public/images/brand.svg")})
    "###
}
.render_md(cx)
```

- **Images, fonts, media, stylesheets, and other opaque files** receive a content-hashed URL such as `/_proa/immutable/favicon.d6018082a1b2c3d4.svg` (16 hex characters) with `Cache-Control: public, max-age=31536000, immutable`.
- **Public JS, HTML, JSON, web manifests, XML, text, and source maps** keep their names under `/_proa/mutable/`, such as `/_proa/mutable/data.json`, with `Cache-Control: public, no-cache` and a strong `ETag` so browsers revalidate them after edits.
- **A hashed file has exactly one URL.** There is no alias at the logical path, so always take the URL from `cx.url("public/...")`. A script that needs the stylesheet URL reads it from the page HTML (`href="/_proa/immutable/styles.<16 hex>.css"`).
- **Root icons** are the one exception: `favicon.ico`, `apple-touch-icon.png`, and `apple-touch-icon-precomposed.png` at the top of `public/` are also answered at `/favicon.ico` and so on (`public, no-cache` plus an `ETag`), because browsers request those paths on their own. An application route at the same path wins.
- **Missing entries** fail rendering with a clear error instead of emitting broken links. Set `paths.public` to `None` in `proa.config.rs` to opt out, or pass an explicit catalog with `FrameworkBuilder::with_public_assets(...)`.

For production, `proa build` writes the catalog beside the executable it exports, in a directory named after the executable with `.assets` appended:

```bash
proa build --locked --artifact-out /out/app   # writes /out/app and /out/app.assets/
```

`app.assets/` is a read-only bundle: a server-only `manifest.json` and a `public/` directory that mirrors browser URLs exactly (`public/_proa/immutable/...`, `public/_proa/mutable/...`, and the root icons). When the app serves RSJS, the bundle also holds the hashed runtime and island modules. Copy the two together, to any directory, and run the binary. A server started without `PROA_PUBLIC_ASSETS` loads the catalog next to its own executable, so a deployment needs no asset path, extra flag, or copy script. Catalog files are world-readable, so a non-root runtime user can load them from a read-only image. Set `PROA_PUBLIC_ASSETS` only to load a catalog kept somewhere else.

### Stylesheet references

Publication rewrites every `url(...)`, `@import`, and `image-set(...)` in a stylesheet that names another public file by relative path, so it points at that file's published location, and then hashes the stylesheet. A changed image therefore renames every stylesheet that refers to it. Your source files are never modified.

```css filename="public/styles.css"
/* Published as url(images/hero.1234abcd5e6f7a8b.webp). */
.hero { background-image: url(images/hero.webp); }
```

References that cannot follow are reported as build warnings: a relative URL that names no public file, a root-relative URL such as `url(/images/a.png)` (use a path relative to the stylesheet), a stylesheet that is not valid UTF-8 CSS, and a reference that leads back to the stylesheet it is in (left as written). Files that keep their names (public JS, HTML, JSON, web manifests) are not rewritten, so a quoted relative path in one that names a hashed file is reported too: nothing is served at that path. Render the file's URL into the page with `cx.url("public/...")` and read it from there.

### Hand-written public JavaScript

Published files are served byte for byte as built, under every base path. Public JS keeps its name under `/_proa/mutable/` and is not rewritten. Pass it what it needs from the page: render the URL of a hashed file into a `data-` attribute with `cx.url("public/...")` instead of hard-coding a path, and read the base path from the page as shown in [coverage and limitations](/docs/framework/deployment#coverage-and-limitations).

### Serving published files from a static host

Set `PROA_ASSET_PREFIX` to link published files from a static host or CDN instead of the app server. See [serving assets from a static host](/docs/framework/deployment#serving-assets-from-a-static-host).

## Serving assets from disk

Use `tower_http::services::ServeDir` for files built into a directory:

```rust filename="src/app.rs"
use axum::Router;
use tower::ServiceBuilder;
use tower_http::services::ServeDir;
use tower_http::set_header::SetResponseHeaderLayer;
use axum::http::header::{HeaderValue, CACHE_CONTROL, X_CONTENT_TYPE_OPTIONS};

let static_router = Router::new().nest_service(
    "/assets",
    ServiceBuilder::new()
        .layer(SetResponseHeaderLayer::if_not_present(
            CACHE_CONTROL,
            HeaderValue::from_static("public, max-age=31536000, immutable"),
        ))
        .layer(SetResponseHeaderLayer::if_not_present(
            X_CONTENT_TYPE_OPTIONS,
            HeaderValue::from_static("nosniff"),
        ))
        .service(ServeDir::new("frontend/dist/assets")),
);

let app = FrameworkBuilder::new()
    .with_static_service(static_router)
    .try_build()?;
```

The final URL for the nested example is `/static/assets/...`. When deployed
under a public prefix, configure `FrameworkBuilder::with_base_path` and use
`cx.url("/static/assets/...")` in templates. The manifest CSS link is
prefixed automatically. See [URL prefix deployments](/docs/framework/deployment#serving-behind-a-url-path-prefix).

When `with_base_path(...)` is configured, the `/static` service also composes
recognized URLs inside CSS and JS/MJS files. CSS `url(...)`/`image-set(...)`/`@import`, module
imports, and native browser request/worker URL arguments follow the mount.
Ordinary strings and external URLs stay unchanged. This applies only to
`/static`; files published from `public/` are never rewritten. See
[coverage and examples](/docs/framework/deployment#coverage-and-limitations).

For routers built without `FrameworkBuilder`, wrap the static router explicitly:

```rust
use proa::axum::{base_path_assets, BasePath};

let static_router = base_path_assets(static_router, BasePath::new("/apps/demo")?);
```

Apply compression outside this wrapper. Its parsed output is cached by content;
ETags and HEAD responses describe the transformed representation. Integrity
hashes must be computed from those served bytes.

A single-binary deploy skips the directory entirely and carries the files inside the executable.

## Embedding assets in the binary

Use `EmbeddedStaticService` when `include_dir` compiles assets into the binary.

```rust filename="src/app.rs"
use axum::Router;
use include_dir::{include_dir, Dir};
use proa::axum::EmbeddedStaticService;

static PUBLIC: Dir<'static> = include_dir!("$CARGO_MANIFEST_DIR/public");

let static_router = Router::new().fallback_service(EmbeddedStaticService::new(PUBLIC.clone()));
```

`Dir` holds only `'static` slices, so the clone copies references, not file bytes.

The embedded service sets a content type from the extension and adds `X-Content-Type-Options: nosniff`.

Either service can host the stylesheet, but the page still needs a link to it.

## Serving linked island assets

RSJS embeds its runtimes and generated module sources in the linked binary.
`FrameworkBuilder` serves them by default:

```rust filename="src/app.rs"
use proa::axum::FrameworkBuilder;

let app = FrameworkBuilder::new()
    .with_dynamic_routes_and_metadata(routes, metadata)
    .try_build()?;
```

| URL | Serves |
| --- | --- |
| `/_proa/immutable/rsjs/runtime.<16 hex>.js` | Core browser runtime. |
| `/_proa/immutable/rsjs/query.<16 hex>.js` | Query and mutation runtime. |
| `/_proa/immutable/rsjs/island/<name>.<16 hex>.js` | Linked island modules, client helpers/classes, and component fragments. |

Every file name carries a hash of its contents and is served with
`Cache-Control: public, max-age=31536000, immutable`. Modules import each other
by relative path and contain no base path; modules that import each other in a
cycle share one hash. The response finalizer selects the script tags and
preloads each page needs and links the hashed names automatically. Every script
and `modulepreload` tag carries the CSP nonce and an `integrity="sha384-..."`
attribute. `with_static_service(...)` continues to serve application files
under `/static` independently.

The fixed paths `/rsjs-runtime.js`, `/rsjs-runtime-query.js`, and
`/rsjs/island/...` are no longer served, so hand-written JavaScript cannot
import the runtime from them.

For a custom Axum router, prepare the files once, merge their router, and hand
the same value to the context layer so pages link the names it serves:

```rust
use proa::axum::{RouteContextLayer, RsjsAssets};

let rsjs = RsjsAssets::prepare()?;
let app = router
    .merge(rsjs.router())
    .layer(
        RouteContextLayer::new(metadata)
            .with_base_path(base_path)
            .with_rsjs_assets(&rsjs),
    );
```

`proa build --artifact-out` stores the same modules in the bundle beside the
executable. A server that finds them there reads them from disk and does not
parse, rewrite, or minify any module at startup.

Call `without_rsjs_assets()` if an application serves its own copies at the
canonical paths instead.

The default RSJS routes work at the origin root or with
[`with_base_path(...)`](/docs/framework/configuration#frameworkbuilder-base-paths-and-rsjs-assets).
The module files are identical under every prefix; only the URLs in the page
change, while incoming routes remain unprefixed and HTML responses keep
streaming. See
[URL prefix deployments](/docs/framework/deployment#serving-behind-a-url-path-prefix)
for proxy setup and [RSJS runtime wiring](/docs/rsjs/runtime) for asset selection
and hydration.

## Linking the application stylesheet

Write the link in the document layout. `cx.url("public/...")` resolves the hashed stylesheet and applies the configured base path or `PROA_ASSET_PREFIX`:

```rust filename="src/layouts/root.rs"
let stylesheet = cx.url("public/styles.css");
html_sync! {
    <link rel="stylesheet" href={stylesheet} />
}
```

## Mounting external apps

Compose additional static applications with Axum's router APIs. For example,
nest a file service at `/docs`. Configure any SPA fallback explicitly on that
service. Proa does not start other dev servers or provide a reverse proxy.

Every path above serves files straight to the browser, which makes what you put in those directories a security decision.

## Securing served directories

- Serve **only** trusted build output from static directories.
- Do not let untrusted users write files or symlinks into served asset directories.
- Add `nosniff` headers for disk-backed services.
- Prefer immutable cache headers only for fingerprinted asset names.
- Keep uploads behind explicit authenticated handlers instead of a generic static file service.
