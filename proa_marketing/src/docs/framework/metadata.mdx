---
title: Metadata and OG images
description: Set page metadata from WebContext and render it in your document head.
---

Use `Metadata` from `proa_core` to declare page metadata. Render its tags once with `{cx.metadata.head()}`.

## Static metadata

In a render method:

```rust
cx.metadata(
    Metadata::new()
        .title("Pricing")
        .description("Plans and deployment options."),
)?;
```

```html
<title>Pricing</title>
<meta name="description" content="Plans and deployment options."/>
```

## Dynamic metadata

Await data before rendering the document. Pass the loaded value to the body:

```rust
let product = cx.load_typed::<Product>(product_key(&self.id)).await?;

cx.metadata(
    Metadata::new()
        .title(product.name.clone())
        .description(product.summary.clone())
        .canonical(product.canonical_url.clone())
        .open_graph(|og| {
            og.ty("website");
            og.images([product.social_image.clone()]);
        }),
)?;

RootDocument { content: ProductBody { product } }.render(cx)
```

Read params, headers, and query strings through the usual `cx.param(...)` and `cx.request()` APIs. Use `load_json` for JSON-backed data or `load_typed` for Rust values; see [Data loading](/docs/framework/data-loading).

## Render the head

Put the emitter inside your document's `<head>`, before rendering the body:

```rust
html_sync! {
    <!DOCTYPE html>
    <html lang="en">
        <head>
            <meta charset="utf-8" />
            <meta name="viewport" content="width=device-width, initial-scale=1" />
            {cx.metadata.head()}
        </head>
        <body>{self.content}</body>
    </html>
}
.render(cx)
```

`RootDocument` is an optional application wrapper for this shell, fonts, and assets. Declare page metadata **before** calling it; a body component is too late. The wrapper should emit metadata without applying competing defaults.

## Reference

### `cx.metadata(value)`

Returns `Result<(), MetadataError>`. Pass a `Metadata::new()` builder; omitted fields inherit. Static literals stay borrowed; dynamic strings must be owned.

| Method | Sets |
| --- | --- |
| `.title(text)` | Document title |
| `.absolute_title(text)` | Title that bypasses inherited templates |
| `.title_template("%s · Acme")` | Template for more specific route scopes |
| `.description(text)` | Description meta tag |
| `.canonical(url)` | Canonical link |
| `.open_graph(\|og\| { ... })` | Open Graph fields and images |
| `.clear_title()`, `.clear_description()`, `.clear_canonical()`, `.clear_title_template()` | Remove the corresponding inherited value |

### `cx.metadata.head()`

Returns a render command. Rendering it writes the current tags immediately and closes declarations, even when empty. Obtaining the command alone takes no snapshot. It works in sync, async, and Send render trees.

Manual head tags remain ordinary HTML. Use one mechanism per field to avoid duplicates.

### Layout defaults

Registered layouts declare defaults in `Layout::setup`:

```rust
impl Layout for SiteLayout {
    fn setup(&self, cx: &mut WebContext<DynLoaderHandle>) -> Result<(), WriteError> {
        cx.metadata(
            Metadata::new()
                .title("Acme")
                .title_template("%s · Acme")
                .open_graph(|og| { og.site_name("Acme"); }),
        )?;
        Ok(())
    }
}
```

Register with `Route::layout(path, &SiteLayout, children)`. Setup runs synchronously, outermost to innermost, before the page. Send responses also require `setup_send(&mut SendWebContext<DynLoaderHandle>)`. See [Routes and layouts](/docs/framework/routing).

### Title templates

With the layout above:

```rust
cx.metadata(Metadata::new().title("Pricing"))?;
// <title>Pricing · Acme</title>

cx.metadata(Metadata::new().absolute_title("System status"))?;
// <title>System status</title>
```

Only the nearest ancestor template applies, once. A template does not format its own scope's default title. It must contain exactly one `%s`; `clear_title_template()` stops inheritance for more specific scopes.

### Canonical URLs

```rust
cx.metadata(Metadata::new().canonical("https://example.com/pricing"))?;
```

Supply absolute HTTP(S) URLs from trusted deployment configuration. Relative URLs, credentials, whitespace, controls, backslashes, missing hosts, and invalid ports are rejected. Proa does not infer a public origin from request headers.

### Open Graph

```rust
cx.metadata(Metadata::new().open_graph(|og| {
    og.site_name("Acme");
    og.ty("website");
    og.images([
        OpenGraphImage::new("https://example.com/og/pricing.png")
            .with_dimensions(1200, 630)
            .with_alt("Acme pricing"),
    ]);
}))?;
```

Calling `.open_graph(...)` enables social tags. Omitted fields use the final document values at emission:

| Open Graph field | Default |
| --- | --- |
| `og:title` | Formatted document title |
| `og:description` | Document description |
| `og:url` | Canonical URL |

Set an override with `og.title(...)`, `og.description(...)`, or `og.url(...)`. Their `clear_*()` counterparts suppress fallback. Other setters are `site_name`, `determiner`, `ty`, and `locale`; `clear_type()` clears `ty`.

`.images([...])` replaces the complete previous list. `.image(...)` appends **within one declaration**; separate declarations still replace. Images support `with_dimensions`, `with_alt`, `with_secure_url`, and `with_mime_type`. Use `og.clear_images()` to remove inherited images. Image URLs follow the same policy as canonical URLs; they are emitted, not fetched or generated.

## Behavior

### Inheritance

Registered route scopes resolve in order: **outer layout → nested layout → page**. Ordinary wrappers share their caller's scope. Later declarations replace only the supplied fields:

```rust
cx.metadata(Metadata::new().title("Search").description("Search the catalog."))?;
cx.metadata(Metadata::new().title("No results"))?;
// Title: No results. Description: Search the catalog.

cx.metadata(Metadata::new().clear_description())?;
// Description is now absent.
```

Open Graph fields merge individually; image lists replace as a unit. Clears affect managed fields only. Client-navigation payloads use the resolved title; a cleared title stays absent.

### Timing and errors

**Load → declare → emit head → render body.** This order is the same for buffered and streaming responses. Suspense children, fallbacks, and detached fragments cannot contribute document metadata.

| `MetadataError` | Cause |
| --- | --- |
| `Closed` | Declaration after head emission |
| `DuplicateHead` | Rendering the managed head again |
| `Ineligible` | Declaration or emission from a deferred/fragment context |
| `InvalidTitleTemplate` | Missing or multiple `%s` placeholders |
| `InvalidUrl { field }` | A URL violates the HTTP(S) policy |

Propagate declarations with `?`; head errors propagate through `WriteError::Metadata`. Invalid patches apply no fields. Failed emissions stay closed, and catching a later error does not roll back earlier declarations.

For streaming routes, decide status, authorization, redirects, and cache policy in the handler **before returning the response**. Metadata cannot reopen committed HTTP headers. Keep unrelated slow data in the body. See [Route responses](/docs/framework/responses).

Cached byte fragments do not replay metadata calls. Cache the complete response with keys that cover any personalized metadata. This API emits HTML metadata; it does not manage Markdown titles or browser-side head patches.

## Migration

| Previous API | Replacement |
| --- | --- |
| `impl Metadata`, `Cascade*`, computed/resolved metadata | `Metadata::new()` in page rendering or layout setup |
| `render_metadata_head(cx)` | `{cx.metadata.head()}` |
| `Route::page_with_metadata`, `Route::with_metadata` | `Route::endpoint` plus page declarations |
| `with_dynamic_routes_and_metadata` | `with_dynamic_routes_and_setups` using plans from `router_from_spec` |

`Route::page(path, title, handler)` still supplies a title-only default. Explicit page declarations override or clear it.
