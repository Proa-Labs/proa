Handle expected failures in your handler or component. Use `ErrorBoundary` when a section can fail during server rendering and the rest of the page can still be useful.

## Handle expected errors

- **Invalid form input.** Return field errors and re-render the form with the submitted values. See [Re-rendering field errors](/docs/guides/forms-actions#re-rendering-field-errors).
- **Missing resource.** Return `404 Not Found` from the handler. Use a [rendered 404 page](/docs/framework/errors#rendering-a-404-page) when the response needs the site layout.

## Recover from render failures

Put the normal content in `ErrorBoundary`’s `child` field and the error UI in `fallback`.

```rust filename="src/components/stock.rs"
use proa::{DataLoader, ErrorBoundary, WebContext, WebRenderSync, WriteError, html_sync};

struct StockCount {
    remaining: Result<u32, WriteError>,
}

impl<L: DataLoader> WebRenderSync<L> for StockCount {
    fn render(self, cx: &mut WebContext<L>) -> Result<(), WriteError> {
        let remaining = self.remaining?;
        html_sync! {
            <p data-stock-count>{remaining}" in stock"</p>
        }
        .render(cx)
    }
}

pub fn product_stock(remaining: Result<u32, WriteError>) -> impl WebRenderSync {
    html_sync! {
        <section aria-label="Stock">
            {ErrorBoundary {
                child: StockCount { remaining },
                fallback: html_sync! {
                    <p>"Stock is temporarily unavailable."</p>
                },
            }}
        </section>
    }
}
```

Passing `Ok(3)` renders the count. Passing `Err(WriteError::render("stock lookup failed"))` renders the fallback. The nearest enclosing boundary handles a recoverable `WriteError` and discards the failed child's buffered output.

Transport failures and managed-head lifecycle errors propagate to the caller. Rust panics follow the server’s panic handling. For a failure that reaches the whole response, see [Handling framework errors](/docs/framework/errors#handling-framework-errors).

### Stream a section with a fallback

For a streamed section, put `Suspense` inside `ErrorBoundary`. Give `Suspense` the loading UI and `ErrorBoundary` the error UI. Bytes already sent stay in the response, and the HTTP status is fixed once headers are sent. See [Streaming SSR](/docs/core/streaming-ssr).
